# 复盘反馈 + 内循环提升（内置到本 SKILL）

> 本 SKILL 不是一次性交付工具，而是一个「越用越强」的闭环：你反馈数据 → 我定位问题 → 单变量优化 → 回填口径 → 回写经验库/references → 下次自动用新口径。

## 一、进化循环

```
你反馈数据 → 漏斗定位 → 单变量优化 → 复盘 → 回写经验库 + references → 下次用新口径
```

## 二、触发节点（什么节点反馈）

| 节点 | 时机 | 你要反馈的最小数据 |
|---|---|---|
| 0-1 测款窗结束 | 上架第 14 天 | 曝光、点击、CTR、加购、成交、转化率、退货 |
| 每周固定复盘 | 每周一 | 漏斗环比 + 四渠道归因 + 达人出单 + 投流 ROAS + 评分 |
| 1-10 放量前 | 第 3-6 周 | 达人出单率/平均出单数、样品成本、GMV Max ROAS |
| 10-99 月复盘 | 每月 | CAC/LTV/AOV/贡献利润 + SKU 分层 + 补货/回款 |
| 99-100 大促/直播后 | 每场结束 | 直播 GMV/场、流量来源、客单价、退货 |
| 100+ 季度复盘 | 每季度 | 品类/店群/跨市场 8 维评分 |
| 任意踩坑/纠错 | 实时 | 报错/卡点/失败原因/我哪份输出错了 |

## 三、反馈数据字段（按类型给最小集）

- 商品卡：曝光、点击、点击率(CTR)、加购、成交、转化率(CVR)、退货/退款。
- 达人/短视频：达人ID、层级、触达、寄样、出片、出单数、达人GMV、佣金。
- 投流：日期、预算、曝光、点击、GMV、直接ROAS、综合ROAS、自然单占比。
- 履约：延迟发货率、跟踪有效率、妥投时效、取消/退货/退款/纠纷、店铺评分。
- 财务实测：实际佣金率、交易费、订单处理费、所得税、VAT/关税、尾程、边境仓费、退款损失。

## 四、我如何协助你复盘提升（固定动作）

1. **收数据 → 定位**：把数据放进漏斗，找最大漏损环节（曝光不足=流量问题；点击低=主图/标题；加购低=卖点/价格；成交低=信任/促销）。
2. **归因**：拆商品卡 / 短视频 / 达人 / 直播四条渠道，判断是流量问题还是转化问题。
3. **单变量优化**：一次只改一个变量（标题/价格/达人佣金/投流素材/促销档），给具体动作 + 预期阈值 + 观测时长。
4. **回填口径**：用实测出单率/费率/退货率替换假设值，重跑单位经济模型，更新保本 ROI。
5. **回写经验库 + references**：带来源+日期+置信度，更新 `experience-library.md` 和相关 references。
6. **固化门禁**：新踩坑 → 补强方案 → 下次自动执行，不重复犯错。

## 五、交付时必带《复盘反馈手册》

每个交付包含一份《复盘反馈手册》，写明：
- 本产品的反馈节点时间表（D14 / 每周一 / 每月 / 大促后 / 季度）。
- 每个节点要填哪张表、哪些字段。
- 发给我时的格式示例（一段文字或一张表都行）。
- 每个节点的「顺利/卡住/更差」数值阈值，方便你快速判断。

## 八、进化门禁（防止污染）

1. 每次补强必须带「来源 + 日期 + 置信度」。
2. 新铁律必须经「踩坑复盘」验证，不凭印象加。
3. 回写只进 references / 经验库，不回写用户交付文件。
4. 冲突时以「官方 + 实测」优先，不确定标注待确认。

## 九、复盘沉淀的「触发方式」（2026-10-10 明确，回答"自动还是手动"）

复盘沉淀分**两层**，触发机制不同：

| 层 | 沉淀到哪 | 触发方式 | 谁负责 |
|---|---|---|---|
| **① 业务复盘内循环** | `experience-library.md` + 回填 `表格/02`、`A-04` + 本 references | **需触发**：8 个节点（D14/周一/每月/大促后/直播后/季度/踩坑/阶段切换）由**用户发数据**发起；或由 `automation` 定时提醒 | 用户发数 + AI 定位 |
| **② AI 工作沉淀** | 项目 `memory/YYYY-MM-DD.md`、`memory/MEMORY.md`；流程变更追加 `workflow-freeze.md` 一行 | **半自动**：会话内完成实质工作后 AI **自觉立即写**（不必用户提）；流程/BUG 类变更**必须**追加 freeze 行 | AI |

**会话内自动触发的三个自审计表**（`workflow-freeze.md` 第三节，属强制动作，不靠记忆）：
1. 开工前置自检（三勾表，进 A 前必贴）；
2. 每步门禁回报（A/B/C/D 各贴 gate 勾选）；
3. 交付前终检（`deliverable-package-spec.md` 八项 + `verify.py`/`crosscheck.py` 通过 + MANIFEST 自查）。

**跨会话/到点触发（需显式设置）**：
- 用 `automation`（定时任务）把「周复盘 / 月复盘」变成闹钟。**本机 2026-10-10 已装 2 条**：
  - `周复盘提醒（TK单品·每周一）`：`FREQ=WEEKLY;BYDAY=MO;BYHOUR=9`；
  - `月复盘提醒（TK单品·每月1号）`：`FREQ=MONTHLY;BYMONTHDAY=1;BYHOUR=9`。
  - 两条都只`提醒 + 列字段`；数据仍需用户给（后台数据 AI 拿不到），**未给数不得编造**。
- **事件型节点**（踩坑即报 / 大促后 / 直播后）无法预排 → 用户即时触发。
- **阶段节点**（冷启动 D14 / 阶段切换 D45·D120）→ 需**上架日**后补一次性 `scheduleType=once` 闹钟。
- 没有 automation 时：**用户在该节点发数据**即是唯一触发（AI 不会自己知道你的销量变了）。

> 一句话：**流程内的门禁是自动的（自审计强制）；到点的业务复盘需要一个"闹钟"（automation）或你发数据来触发。**

## 十、2026-10-10 全天复盘结论（生肖守护神钥匙扣包全程）

**三个被验证有效的机制**：
1. **官方第一原则立刻见效**：本地扫描一次纠正 3 个关键数值（直邮费 5,400→3,000₫、佣金 14→14.5%、退回仓费 2,000→Zone 均值 31,929₫）——二手 estimated 与官方值的偏差可达 ±80%，**任何 estimated 值都不该进最终定价**。
2. **口径变更必须全链路重算**：脚本→输入 JSON→全部活表→全部文档→网页→三端，漏一环就出「文档与表格打架」。本轮用「grep 旧值全包扫描」兜底，有效。
3. **用户口径即规则**：模式不清零只匹配、退回仓=Zone 均值、货代费直邮照收——用户的一句口径胜过工具的"聪明默认"，凡用户口径都要写进 freeze 并标来源与日期。

**暴露过的问题模式（防复发）**：
- 代入串漏项（贡献利润_代入漏达人佣金与投流费）→ **机检新增「代入串等式自洽」**（crosscheck.py，2026-10-10）。
- schema 变更打崩旧脚本（T23 logistics.json 无 records → tk_distill 崩）→ **改数据结构必须 grep 所有消费方**。
- 协议编号重复、子 SKILL 落后主 SKILL → **改主 SKILL 后必须 grep 子 SKILL 同步点**（本轮已把国家门禁补进 4 个子 SKILL）。

**首个 vat_base>0 真实用例的完整经验**：跨境直邮+VAT 代扣口径已跑通全链路（unit_economics → 表格 → 机检），后续直邮包直接复用 `ue_*.json` 模板。
