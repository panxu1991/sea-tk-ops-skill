# 经营模型（已锁定 + 可切换适配）

## 当前锁定模型

跨境 POP 自运营店铺 + 京东边境仓（贴面单/打包/清关/跨境头程）+ 平台越南尾程。

- 尾程运费买家付（`last_mile_fee=0`），但仍计入 6% 交易费基数。
- 边境仓模式平台默认不代扣进口 VAT（`vat_base=0`）；所得税 1% 代扣。
- 待核验项见 `policy-snapshot.md`（边境仓计费、尾程交接、退货回程）。

## 模式切换触发

当用户说「改用直发 / 越南本土仓 / 平台仓(FBT) / 海外仓 / 第三方 3PL」等任一履约或经营模式变化时：

1. **停用旧口径**：本模型下的费率/税/履约/退货假设全部标记「待重核」，不沿用。
2. **深度检索**：用 `official-source-map.md` 的入口 + 当前官方文章/PDF，重新核验：佣金、交易费、订单处理费、所得税、进口 VAT、高价值关税、保证金、履约时效、退货回程、资金链/回款。
3. **权威补充**：调 `research` / `nexscope-frameworks.md` 的履约模型对比（直发/本地3PL/平台仓/代发/跨境集运），给切换 tradeoff（费率/时效/压货/现金流/退货）。
4. **形成新方法库**：把新模型的口径写入一份新的 model snapshot（带日期 + 来源），供输出时调取；旧模型 snapshot 保留但标注「已退役」。
5. **重跑单位经济**：`unit_economics.py` 用新费率/新履约成本重算双体系盈亏与保本 ROI。

## 边界

- 不做越南法律/税务意见的最终判定，只做「官方口径 + 权威框架」的规划口径，冲突时标注待卖家中心/官方确认。
- 模式切换是不可逆/高影响决策，先出方案给用户确认，再替换默认模型。
