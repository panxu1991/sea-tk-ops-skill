# 东南亚 TK 运营全域交付

> 本 SKILL 是「TikTok 跨境电商运营引擎」的**独立可移植版**：修复了原版依赖外部「维护包」、表格构建器缺失、元技能缺失、硬编码本机路径等 BUG，使**换电脑 / 换 AI 客户端后，交付数量、质量、流程与当前一致**。
> 配套三份内置文档（安装/清单/机制，均在本目录）：
> - **`安装说明.md`** —— 如何在任意电脑 / WorkBuddy / Claude / Codex / Cursor / 豆包 上安装并自检。
> - **`交付清单.md`** —— 冻结的交付物清单（14 文档 + 8 活表 + 图片 + _build，缺一不可）。
> - **`运营测机制说明.md`** —— 运行机制（A→B→C→D 流水线 + 脚本门禁）与测试/机检机制详解。

> 📁 **脚本执行根目录约定（所有客户端通用，必读）**：本技能所有 `python scripts/*.py` / `python scripts/<包>/...` 命令都必须从**技能根目录**执行。各客户端技能根目录不同，调用前先 `cd` 到对应目录（或写绝对路径），否则脚本找不到 `scripts/` 会直接失败：
>
> | 客户端 | 技能根目录 |
> |---|---|
> | WorkBuddy | `~/.workbuddy/skills/sea-tk-ops` |
> | **Claude Code** | `~/.claude/skills/sea-tk-ops` |
> | Codex | `~/.codex/skills/sea-tk-ops` |
> | 豆包 | `~/Doubao/skills/sea-tk-ops` |
>
> 例（Claude Code 开工）：`cd ~/.claude/skills/sea-tk-ops && python scripts/preflight.py`
> 依赖：`openpyxl`（表格必需）+ `requests`/`pdfplumber`/`bs4`（官方取数可选）。缺则开工跑 `python scripts/deps_check.py --install-cmd` 按提示装（已内置隔离 python，见 `安装说明.md`）。

> ⛔ **硬性最小执行序（T38，不可跳过）**：① 开工第一条命令 = `python scripts/preflight.py`（退出码≠0 不得进 A）；② 宣布交付前 = `python scripts/verify_baseline.py <包目录>`（非全绿不得交付）。细则见「开工前置」+ `references/workflow-freeze.md` T38。

## 使命

**一张图 / 产品链接 → 自动跑完整流水线 → 调研、竞品、选品、定价盈亏、全阶段 SOP + 持续出单引擎 + 复盘反馈内循环提升**。全程质量锁 + 输出固化标准，按方法论、按流程、不打折扣执行。

> 本 SKILL 不产出文案、主图、详情页、短视频（这些环节已从本 SKILL 移除）。
> 完整剔除/保留清单见 `references/scope-decisions.md`（有意剔除，非遗漏；恢复需显式授权并三处同步）。

## 需求总纲（8 维度，见 references/requirements-master.md（8维度） + references/core-requirements-13.md（13项核心还原））

1. 总目标：发链接自动交付全套运营包。
2. 经营模型：跨境 POP + 京东边境仓 + 平台尾程（锁定）；改模式则深检索形成另一套方法库（见 business-model.md）。
3. SKILL 建设：一张图/链接自动流水线 + 4 子 SKILL + 质量锁 + 输出固化 + 自循环。
4. 费率与单位经济：两套盈亏体系 + 达人出单率 + 纸箱分级（硬要求）。
5. 选品与竞品：头部/腰部/尾部 + 180 天销量环比 + 做得好/不好复盘（见 selection-and-sourcing.md）。
6. 流量入口与自然流（见 traffic-sources.md）。
7. 自动化/浏览器/工具（见 orchestration.md）。
8. 数据复盘与自循环（见 evolution.md）。

## 开工前置（每轮必跑，2026-10-10 增补，不可省）

> 顺序：**STEP 0 官方优先取数 → STEP 0.5 用户输入集中收集（一次问完，之后零打断）→ STEP 1 目标国家 + 履约门禁 → STEP 2 资料库刷新 → STEP 3 来源探测 → 再进 A→B→C→D**。
>
> **唯一入口（T38-P1）**：上述前置检查 + 依赖自检 + 子 skill 同步已合并为一条命令——开工第一条命令跑 `python scripts/preflight.py`，输出「机器生成四勾表」文本块（**原样贴入 00**）+ 退出码；**退出码≠0 停在对应 STEP，不得进 A**。无交付包 / 无冻结源时 restore·sync 项自动标 SKIP 不阻塞（换机首跑通路，见第 7 条）。

0.5. **STEP 0.5 · 用户输入集中收集（T33，2026-10-10 用户锁定）**：把全流水线所有「需要用户出手」的事项**一次性集中在开工最前面收齐**，收齐后 A→B→C→D 全程不再向用户弹任何确认。清单：
   - ① 目标国家 + 履约模式（或读 `<包>/00` 口径绑定，命中即跳过）；
   - ② 收样实测重量（weight_g）；
   - ③ 国内头程 / 货代贴单 / 包装报价（¥/件）；
   - ④ 首档定价确认（不答用 SOP 默认）；
   - ⑤ 货源确认 + 卖家中心数据（若本轮需要）；**提醒用户提前打开并登录卖家中心**（前置，不中途等）。
   全部写入 `<包>/_build/backfill.json`（null=沿用假设并标注）；未给项按默认+assumed 继续跑，**不阻塞、不二次追问**。

0. **STEP 0 · 官方优先取数（第一原则，2026-10-10 锁定）**：见 `references/source-priority.md`。
   - **先跑 `python scripts/local_official_scan.py`**（只读）扫本地已下载的官方文件（佣金率表 PDF / 东南亚跨境物流运费价格表 xlsx / 边境仓价卡 等常年就在本机）。
   - 顺序：**① 本地官方文件 → ② 官方下载入口下载 → ③ 权威论坛/权威发言/高赞（必须标出处+日期+置信度）**。命中即读取并写入 `references/knowledge-base/`。
   - **禁止**把二手转载当官方写入资料库；冲突一律留白待官方复核。
1. **STEP 1 · 目标国家 + 履约模式 + 边境仓 + VAT 门禁（决定全部盈亏口径）**：见 `references/border-warehouse-gate.md` + `references/country-matrix.md`。
   - ⭐ **一次性绑定（2026-10-10 铁律）**：首次选择后答案写入 `<包>/00-履约确认与来源快照.md`「口径绑定」小节；**同一策略包生命周期内（含跨会话续跑/回填重算）先读 00，命中即视为已过门禁，不再弹窗**。仅用户主动换口径或 00 缺失时重问。
   - **先确认「做哪个国家」**（VN/TH/MY/PH/SG 或 **东南亚所有国家 ALL-SEA**）；不答默认 **越南(VN)** 并标假设。
   - **若选 ALL-SEA → 必须对所有国家做整体策略交付，并按数据给出「建议国家排序 + 首站/次站/观望」**（追加 `A-05/A-06/表格08/B-02/C-05`）。
   - 再确认**履约模式**；若边境仓 → 追问**哪一个仓** + **是否平台代扣 VAT** + **仓内打包费/跨境运输费/清关费/仓储费**（清关费可由用户报价，一次后沿用直到更新）。
   - **两套计价互斥**（脚本按 `fulfillment` 字段自动匹配：`apply_mode_rules()` 定 VAT 基数 + `mode_cost_sum()` 按模式取成本项，**不清零输入**）：直邮 = 采购+国内头程+货代贴单费+跨境物流费+VAT代扣；边境仓 = 采购+国内头程+仓内打包费+贴单费+跨境运输费+清关费+仓储费(90天后)+VAT(0)。**尾程均买家承担；样品尾程卖家承担。** 其余平台费用按平台最新规则。
2. **STEP 2 · TK 官方资料库刷新**：见 `references/tk-official-distillation.md`。
   - 跑 `python scripts/tk_distill.py --check` → 抓取公开页 → `--from-dir` 蒸馏 → 更新 `references/knowledge-base/` + 回写 `policy-snapshot.md`。
   - 刷新：各国佣金(表下载)/退换货/交易手续费/跨境物流费(表下载)/代扣税费/关税/所得税/最新政策/最新汇率/最新教学课程。
3. **STEP 3 · 来源探测 + 自动化取数**：见 `references/source-automation.md`。
   - 跑 `python scripts/source_probe.py --check`；顺利→直接取数；被阻断→在 `A-调研/来源日志.md` 标注 + 给用户配合方案（不停机）。
4. **开工前置自检（100% 触发，不可省）**：进 A 之前必须在回复里输出「开工前置自检」四勾表（STEP0 官方取数、STEP1 国家+模式/仓/VAT、STEP2 快照日期、STEP3 阻断项），全勾才进 A，未勾停在 STEP 处。**T38 起四勾表由 `python scripts/preflight.py` 机器生成（禁止手写），并以原文贴入 00。** 详见 `references/workflow-freeze.md` 第三节。
   - **依赖自检（防机检静默降级）**：开工前跑 `python scripts/deps_check.py`；缺必需项（openpyxl 等）会让表格/PDF/OCR 机检静默空转、误以为检过，必须按降级提示安装后再交付。
   - **子 skill 同步**：改主 SKILL.md 的 SYNC-BLOCK 核心规则后，跑 `python scripts/sync_subskills.py` 把门禁/锁同步进 4 个子 skill（幂等），避免子 skill 各自漂移。
5. **防自动还原漂移（自包含，不依赖外部维护包）**：技能目录 `scripts/` 可能被 AI 客户端自动还原回 BUG 版。开工跑 `python scripts/restore_skill.py --quick`：比对随包内置的 `scripts/integrity-manifest.json`（SHA256 清单），不一致即提示「漂移」。有意改动后跑 `python scripts/restore_skill.py --seal` 重建基线。详见 `references/workflow-freeze.md` 第四节。
6. **改源后同步到其它 AI 客户端（自包含）**：本机可能同时用多个 AI 后台（WorkBuddy / Claude / Codex / Cursor / 豆包 等）。任何对源 SKILL 的改动后，跑 `python scripts/sync_to_backends.py --apply` 干净镜像到所有已探测客户端，并用 `python scripts/verify_backends.py --semantic` 校验多端一致。详见 `references/workflow-freeze.md` 第五节。
7. **新机器首跑（换机 / 新环境，T38-P5）**：
   - ① `python scripts/deps_check.py --install-cmd` → 先装缺项（缺必需项会让表格/PDF/OCR 机检**静默空转**）；
   - ② `python scripts/preflight.py` → 完整性自检/多端核验找不到对应项时自动 SKIP 不阻塞 → 退出码 0 → 进 A；
   - ③ 完整安装与自检步骤见 **`安装说明.md`**（首次安装后跑一次 `restore_skill.py --seal` 建立完整性基线）。

## 执行协议（AI 必须严格遵守，不得自行省略）

0. **前置锁**：每轮先过「开工前置」STEP 1-3（履约门禁 / 资料库刷新 / 来源探测），未过不得进 A。
1. **顺序锁**：严格 A 调研 → B 选品 → C 交付 → D 运营，不跳步、不合并、不反向；每步产出落盘后再进下一步。
2. **门禁锁**：每步「门禁」未全勾不得进入下一步；跳过即重做该步。
3. **输出锁**：每步按 subskill「输出」清单逐项产出，不得删减、合并、简化；少一项视为未完成。
4. **脚本锁**：凡有确定性脚本的环节（选品 / 单位经济 / 运营追踪表 / 看板 / 官方蒸馏）必须跑脚本并用脚本结果，不得手算或脑补。
5. **事实锁**：费率、竞品销量(含单量)、时间维度必须带「来源 + 日期 + 置信度」；拿不到就留白 + 备注需要什么动作，不得编造。
6. **深度锁**：每个结论必须「锁方法论 + 带来源 + 写 WHY」，见 `references/output-standard.md`。
7. **形态锁**：表格/文档判定 + **表格 10 条**硬要求（含「公式计算进表」与「达标通用式」）必须执行，见 `references/output-standard.md`。
8. **自查锁**：交付前逐项勾「质量锁 + 输出固化 + 输出清单」，全勾才交付，并在最终回复里贴出自查结果。
9. **汇率锁**：全文件汇率统一用**实测基数**（`knowledge-base/fx.json` 当日值），见 `unit-economics.md` 第 5 条。
10. **退货率锁**：按三原则取值（实测均值 → 目标国平台均值 → 假设10%），落第三原则须写明前两项未获取原因，见 `unit-economics.md` 第 6 条。
11. **双币种锁（2026-10-10 加强，用户确认）**：**凡出现金额，必须 ¥(CNY) 与目标国币种并行**——表格里做成**相邻两列**、文档里并列写出，**不得只给单币种**（售价/成本/平台费/利润/保本价/样品成本/投流花费等一切金额项）。所有计算值写明公式与代入过程，见 `unit-economics.md` 第 7/8 条 + `output-standard.md` 硬要求第 11 条。
12. **VAT 锁**：跨境直邮以官方为准；边境仓须经 STEP 1 确认是否平台代扣，未确认默认不代扣并标假设。
13. **官方优先锁（2026-10-10）**：任何取数先跑 `local_official_scan.py` 扫本地官方文件 → 再官方下载 → 最后二手（**标出处+日期+置信度**）。官方已公开的（尤其跨境物流价卡、佣金率表，官方页有「下载」）**必须用官方值**，禁止拿二手转载冒充实测/官方。
14. **计价模式锁（2026-10-10）**：**直邮与边境仓是两套互斥计价**——直邮=采购+国内头程+货代贴单费+跨境物流费+VAT代扣；边境仓=采购+国内头程+仓内打包费用+贴单费+跨境运输费+清关费用(可用户报价，一次后沿用)+仓储费(90天后)+VAT(0)。切换由脚本按 `fulfillment` 自动匹配（`apply_mode_rules()` 定 VAT 基数 + `mode_cost_sum()` 按模式取成本项，**不清零输入**），**不得两套混算**。尾程买家承担；**样品尾程卖家承担**；其余平台费用按平台最新规则。
15. **国家锁（2026-10-10）**：开工第一步先确认目标国家（默认 VN；换国家必须重刷 `knowledge-base/`）；选 **ALL-SEA** 时须对全部国家做整体策略并给出**建议国家排序（首站/次站/观望）**，依据 = 各国官方费率/物流卡 + 竞品数据 + 合规难度。
16. **投流门禁锁（2026-10-10）**：投流「续投/翻倍」条件 = 直接ROAS≥阈值 **且** 各渠道综合净利润≥0，见 `unit-economics.md` 第 10 条。

> 保本/保本ROI 口径以 `references/break-even-roi-rule.md` 为准：保本是纯商品卡盈亏平衡（不含达人/投流）；每个定价额外输出 保本ROAS_商品卡 与 保本ROAS_达人 两值。
> 每个运营模式（商品卡/达人A/达人B/达人0）输出三组值：常态 / 盈亏平衡档（反解不亏的关键变量）/ 压力档（最差情形，#14），见 break-even-roi-rule.md + core-requirements-13 #15。
## 交付输出清单（总，缺一不可）

> **固化标准（数量/种类/明细/分析路径/质量）见 `references/deliverable-package-spec.md`**：交付物必须与其中定义的目录树、14 文档 + 6 活表 + 图片(≥11) + _build 数量基线、每文件明细、分析路径、质量锁完全一致；少一项/错一类 = 未完成。

## 复盘反馈 + 内循环提升（内置，见 references/evolution.md）

**你反馈数据 → 我定位问题 → 单变量优化 → 回填口径 → 回写经验库/references → 下次用新口径。**

- 反馈节点：0-1 上架第 14 天、每周一、每月、大促/直播后、季度、任意踩坑。
- 反馈数据：漏斗(曝光/点击/加购/成交)、四渠道归因、达人出单率/出单数、投流 ROAS、退货/退款/评分、财务实测费率。
- 我如何协助：定位漏损环节 → 渠道归因 → 一次改一个变量 → 回填实测口径 → 沉淀经验库 → 固化门禁。
